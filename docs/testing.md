# Testing & acceptance

组件不是「能显示」就算完成。下面这份清单是发布前的最低验收。

## 1. 自动校验

先跑：

```bash
python scripts/validate.py
```

它会检查 manifest、IR、目录、示例与 fixtures：

- [x] `widget.json` 可解析、`schema=1`、必填字段齐全
- [x] `id` 至少两段、格式合法、全局唯一
- [x] `version` / `runtime` / `engine` 是合法 semver / range
- [x] `type` 与 `ui` 扩展名匹配
- [x] 路径不逃出包根，不含反斜杠、盘符、`..`
- [x] `ui` / `locales` / `assets` / `fonts` 指向的文件存在
- [x] `permissions` 覆盖 `data[].source` 与 IR 用到的命令
- [x] `network` 与 `network` 权限同时出现，域名合法
- [x] `settings[].key` 唯一、默认值类型正确、在范围内
- [x] IR 节点 / 属性白名单通过
- [x] 绑定表达式只使用允许的语法；根名在 `data` / `settings` / `item` 内
- [x] `image.src` 的资源已声明且存在
- [x] 单文件 / 总包大小在上限内
- [x] 没有 `eval` / `new Function` / 远程脚本（script，静态扫描）

CI 会在每次 push / PR 跑同一份脚本。它不替代手工验收，只负责把「结构错误」挡在门外。

## 2. 视觉矩阵

按**卡片内容宽**截图，不是按面板宽。面板宽只是入口：

| 面板宽 | 列数 | 单跨内容宽 | 场景 |
|---|---|---|---|
| 320 | 1 | 254 | 最窄 rail |
| 384 | 1 | 318 | 默认 rail |
| 485 | 2 | 190 | 两列刚成立 |
| 660 | 2 | 273 | board |
| 714 | 3 | 185 | 三列刚成立，**最窄卡片** |
| 920 | 3 | 253 | wide |
| 1180 | 3 | 340 / 1110 | 单跨 / 跨三列 |

至少检查：

- [ ] 185px 下没有横向溢出、文字重叠、裁切
- [ ] 1110px 下没有把内容拉成一条细线
- [ ] 单跨与跨列两种布局都正常
- [ ] 高度由内容决定，不被强行撑满或压扁

语言 `zh` / `en` 各一遍。中文额外检查：

- [ ] 最小字号 ≥ 10.5px
- [ ] 字距不过度拉伸（中文 caption 不用 0.17em）
- [ ] 浅色说明文字对比度足够（正文 ≥ 4.5:1，大字号 ≥ 3:1）
- [ ] 中英混排没有基线跳动
- [ ] 长中文标题按 `maxLines` 截断，不撑破卡片

DPI：Windows 缩放 **100% / 125% / 150%** 各看一次。逻辑 px 不变，但发虚、裁切、点击目标
变小的问题只会在高 DPI 下暴露。

主题：至少 `Clear`、`Lagoon`、`Dusk`、`Ember` 四套；检查强调色、玻璃背景、深浅对比。
八套全过更好，但不作为 v1 的硬门槛。

## 3. 交互

- [ ] 鼠标悬停、点击、键盘 Tab / Enter / Esc 都能完成主路径
- [ ] 焦点环可见；图标按钮有可访问名称
- [ ] 输入框支持 Esc 取消 / Enter 提交（脚本组件）
- [ ] 中文输入法组合态下按 Enter 不误提交，按 Esc 不误收面板
- [ ] 删除 / 清空有撤销或确认（脚本组件）
- [ ] 组件不抢焦点、不注册全局快捷键
- [ ] 面板收起再唤出后状态正确
- [ ] 切换语言后文案即时更新，不残留旧语言
- [ ] 主题切换后 canvas / SVG 重绘，不残留旧颜色

声明式 v1 没有输入框与逐行动作，不要按这两条去测不存在的功能。

## 4. 数据与错误

- [ ] 数据未就绪时显示占位，不抛错
- [ ] 数据源失败时保留上一次值或显示错误态
- [ ] 数据更新不会造成整卡闪烁 / 布局跳动
- [ ] 卸载后没有定时器 / 监听器泄漏
- [ ] 脚本崩溃只影响当前卡片
- [ ] 网络失败 / 超时不会卡住面板
- [ ] provider 为 `null`、数组为空、字段缺失三种情况都有定义好的表现

## 5. 性能

测量方法：同一台机器、面板 384 宽、单卡、连续 20 次取中位数；不要只报最好的一次。

- [ ] `mount` < 50 ms
- [ ] 常规 `update` < 8 ms
- [ ] 没有 >10 Hz 的自建轮询
- [ ] 动画只改 `transform` / `opacity`
- [ ] 连续开合面板 20 次，内存增长 < 8 MB
- [ ] 1180 宽 + 3 列下不横向滚动
- [ ] 脚本组件常驻内存 < 8 MB（硬上限 64 MB）

## 6. 减少动态效果

- [ ] `prefers-reduced-motion: reduce` 下关闭非必要动画
- [ ] 状态仍然可读（不能只靠动画表达完成 / 错误）
- [ ] 平滑插值直接落值，不保留缓动

## 7. 安全

声明式组件：

- [ ] 只申请实际使用的最小权限
- [ ] 没有硬编码凭证 / token
- [ ] 网络域名在 manifest 白名单内
- [ ] 不读取包外文件
- [ ] `image.src` 只指向已声明资源

脚本组件额外：

- [ ] `eval` / `new Function` / 远程脚本被拒绝
- [ ] 直接 `fetch` / `XHR` / `WebSocket` 被拒绝
- [ ] 读不到宿主 DOM、localStorage、cookie
- [ ] 读不到其他组件的存储
- [ ] `postMessage('*')` 不承载敏感数据
- [ ] 安装包解压后没有意外文件
- [ ] 卸载后组件目录与存储都被删除

## 8. 手工收益检查

最后问三个问题：

1. 这张卡在 318px（默认 rail）下，用户能不能在 3 秒内读出最重要的信息？
2. 它是否比 Sill 自带组件更值得占用一块玻璃？
3. 删掉它，面板会不会更好？

如果第 3 个问题的答案是「会」，组件还不该发布。
